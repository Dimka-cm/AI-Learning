# Агент — «скрещение обученных ИИ с переключателем»

Ты описал не одну модель, а **агента**, устроенного как я: есть воркспейс
(инструменты), зрение, память — и всё это работает по твоим просьбам.
Разница в том, что его «воркспейс» = **твой ПК**, а «глаз» = твоя 2D-модель
(уже на обучении), к которой позже добавится 3D.

## Архитектура (как это «скрещено»)

```
                    ┌──────────────────────────────┐
   твоя просьба ──▶ │  РОУТЕР (переключатель)       │
                    └──────────────┬───────────────┘
         ┌─────────────┬──────────┼──────────┬─────────────┐
         ▼             ▼          ▼          ▼             ▼
      chat-эксперт  code-эксперт math      vision      инструменты ПК
      (ruGPT-3)     (C/C++/C#)   (AST)     (2D; 3D-загл.)  (файлы/команды)
         │             │
         └──────┬──────┘
                ▼
            ПАМЯТЬ (история + знания JSON)
```

Ключевая идея: **не одна большая модель делает всё**, а несколько экспертов,
между которыми роутер переключает запрос. Каждый эксперт — отдельно обученная
способность. Роутер детерминированный (правила), его можно заменить на
LLM-классификатор, когда чат-модель дообучится — интерфейс `route()` не меняется.

## Что уже работает (проверено живым прогоном)

- **Математика** — надёжно через словарь операторов, а не угадыванием нейронки:
  `python -m agent.cli --say "2+2*2"` → `6`.
- **Инструменты ПК** — файловый слой в песочнице:
  - `/list` — файлы в воркспейсе;
  - `/write путь##текст`, `/read путь`, `/mkdir путь`;
  - `/run команда`, `/delete путь` (с подтверждением);
  - **dry-run** (`--dry-run`): агент проговаривает действие, ничего не трогая;
  - **sandbox**: всё по умолчанию внутри `~/AgentWorkspace`, выход — только
    через `allow_extra_roots` в `config/agent_config.yaml`.
- **Зрение-заглушка** — маршрут `vision` готов, веса «глаза» кладутся в
  `models/eye_2d.pt` (см. `agent/vision.py`).
- **Память** — короткая история (`agent/memory/history.jsonl`) + долгая
  (`knowledge.json`).

## Как это мапится на твою формулировку

| Ты сказал | Как реализовано |
| --- | --- |
| «как ты, но вместо воркспейса мой ПК» | `agent/tools.py` + `~/.config`… (`config/agent_config.yaml` → `tools.workspace`) |
| «2Д/3Д зрение, 2Д уже на обучении» | `agent/vision.py`: `PytorchClassifier` (2D, подключаешь веса), 3D — заглушка с готовым интерфейсом |
| «скрещение нескольких обученных ИИ» | `agent/experts.py`: chat / code / math / vision — отдельные блоки |
| «с переключателем, если надо» | `agent/router.py`: `route()` направляет запрос нужному эксперту |
| «память, разговор, математика» | `agent/memory.py` + эксперты |

## Запуск

```bash
python -m agent.cli                    # интерактивный режим
python -m agent.cli --say "2+2*2"      # разовый запрос
python -m agent.cli --say "/list"      # файлы в воркспейсе
python -m agent.cli --dry-run --say "/write x.txt##привет"   # безопасный прогон
python -m agent.cli --allow-dangerous  # разрешить delete/run без вопросов
```

На ноуте — то же самое, `python -m agent.cli` (Windows: `py -m agent.cli`).

## Дорожная карта (что подключается по мере твоих обучений)

1. **Чат**: дообучи ruGPT-3 (см. `docs/SELF_HOSTED_RUNNER.md`) → в конфиге у
   эксперта `chat` указан `model`; после обучения переставь на свой чекпоинт.
2. **Код**: дообучь вариант на C/C++/C# → замени `code: kind: stub`.
3. **Глаз 2D**: положи веса в `models/eye_2d.pt` → `vision.kind: torch` уже стоит.
4. **Роутер-LLM**: когда чат-модель будет понимать сложные просьбы, замени
   правила на классификатор (спроси меня — сделаю).
5. **События ФС (опционально)**: «следить за созданием/изменением файлов» —
   добавлю watcher, если нужно.

## Безопасность (важно)

- Агент ограничен своей папкой и never не ходит в системные места без allowlist.
- Удаление/запуск требуют явного разрешения (`--allow-dangerous`).
- `dry_run` — лучший режим, чтобы посмотреть, ЧТО агент сделал бы.
- Команды с `rm -rf /`, `format`, `shutdown`, `reg ` и т.п. блокируются всегда.
