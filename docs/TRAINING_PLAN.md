# План дообучения модели по опросу владельца

Дата фиксации профиля: 2026-09-21.

## Цель

Модель нужна не как «энциклопедия на всё», а как русскоязычный мозг ПК-агента:

- живой русский диалог;
- программирование;
- Minecraft modding: Forge / NeoForge / Fabric / Mixins / Gradle;
- Unreal Engine 5 и Blueprint;
- объяснение математики;
- работа через инструменты агента: файлы, команды, Gradle, позже экран/мышь;
- интернет позже отдельным инструментом поиска, чтобы не выдумывать свежие факты.

Полный машинно-читаемый профиль лежит в `config/training_profile.yaml`.

## Характер

- на «ты», как к владельцу/создателю;
- дружелюбно, спокойно, как друг;
- можно грубовато и с юмором, но **не оскорблять пользователя**;
- если не знает — честно говорит «не знаю» и предлагает поискать;
- свежие факты после 2019 года лучше брать из интернет-инструмента, а не выдумывать.

## Безопасность ПК-агента

Без подтверждения нельзя:

- удалять файлы;
- запускать `.exe`;
- менять системные настройки;
- вводить пароли;
- покупать/оплачивать;
- отправлять сообщения от имени владельца;
- лазить в папки, требующие права администратора.

Даже если владелец хочет «всё сам», реализация должна оставлять confirm/dry-run для опасных действий.

## Важное про корпус владельца

Корпус владельца — большой **русско-английский** художественно-разговорный текст без упора на программирование. По примеру это скорее **художественная проза / роман с диалогами**, а не Q/A-инструкции. Это хороший формат для обучения русского языка, простого английского текста, связной речи, описаний, диалогов и общего стиля, но кодовые навыки он сам по себе не даёт.

Для текущего корпуса ничего специально размечать не нужно: `steps/step_00_prepare.py` читает обычные строки/абзацы как учебные блоки и раскладывает их в `text`-порции `shard_01..04`.

Объём корпуса большой: примерно **6.5 ГБ**, **46 508 165 строк**, 7 частей, последняя около **460 МБ**, остальные больше 1 ГБ. Поэтому полный Drive-корпус не надо первым делом гонять на GitHub Actions. Сначала нужен маленький smoke: отдельный `.txt`-кусок 25–100 МБ или `data_limit_mb` больше размера выбранной части. Код Drive-загрузки теперь пропускает `.txt`, которые больше остатка лимита, чтобы случайно не скачать гигабайтный файл при лимите 25 МБ. Токенизация тоже оптимизирована под такой объём: блоки кодируются батчами (`TOKENIZE_BATCH_SIZE`, по умолчанию 1024), а не 46 млн отдельных вызовов токенизатора.

Дополнительно токенизатор умеет не разрывать пары с маркерами `Пользователь:`, `Вопрос:`, `Агент:`, `Ответ:`. Это пригодится, если позже появится отдельный Q/A или instruction-датасет.

## Первый реальный прогон в GitHub Actions

Workflow: **«Дообучение в Actions»**.

Рекомендуемые inputs для общего smoke на HF:

```text
data_source: hf
hf_dataset: Imperius/ru-classic
data_limit_mb: 25
start_step: 1
end_step: 2
max_steps: 300
```

Рекомендуемые inputs для прогона **одной части** Drive-корпуса. В папке `library` файлы называются `merged_data_1.txt` ... `merged_data_7.txt`:

```text
data_source: drive
drive_folder_url: <ссылка на папку library>
drive_file_regex: ^merged_data_1\.txt$     # номер меняется 1..7
drive_max_files: 1
data_limit_mb: 1200                       # больше размера выбранной части; для 7-й можно 500-600
drive_budget_s: 3600
start_step: 1
end_step: 4                               # text-домен раскладывается в shard_01..04
max_steps: 300
resume_run_id:                            # пусто для первой части
```

Чтобы обучение **накапливалось** между частями на GitHub Actions, у второй и следующих частей нужно указать `resume_run_id` предыдущего успешного run. Workflow скачает артефакт `ci-checkpoint-progress`, восстановит `checkpoints/**` и включит `RESUME_FROM_LATEST=1`, чтобы шаг 01 продолжил с последнего чекпоинта прошлой части.

Пример цепочки:

```text
часть 1: drive_file_regex=^merged_data_1\.txt$, resume_run_id пустой
часть 2: drive_file_regex=^merged_data_2\.txt$, resume_run_id=<run id части 1>
часть 3: drive_file_regex=^merged_data_3\.txt$, resume_run_id=<run id части 2>
...
часть 7: drive_file_regex=^merged_data_7\.txt$, data_limit_mb=600, resume_run_id=<run id части 6>
```

Успех первого прогона:

- есть `checkpoints/step_01/last.pt`;
- есть `logs/progress.svg`;
- loss падает;
- `logs/eval_answers.md` показывает, что модель генерирует русский текст и не ломается на простых английских промптах.

## Оценка качества

Промпты для ручной оценки лежат в `eval/model_quality_prompts.yaml`.
После обучения workflow запускает:

```bash
python scripts/evaluate_prompts.py --limit 12 --out logs/eval_answers.md
```

Плохой ответ:

- врёт;
- на русский запрос пишет не по-русски;
- путает русский и английский без причины;
- не понимает Minecraft;
- не признаёт ошибку.
