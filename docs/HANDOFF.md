## 1. Что это за проект

Русскоговорящий **ПК-агент** + пайплайн **дообучения** языковой модели (ruGPT-3 Small).
Репо: `Dimka-cm/AI-Learning`, ветка работы `arena/01a0bdc7-ai-learning`, base `main`.

## 2. Чего хочет владелец (полная картина целей)

1. **Текстовый ИИ на русском**: память, разговор, математика.
2. Правило поведения: «не обзываться»; остальное — без жёсткой цензуры
   (вредный/противозаконный контент целенаправленно НЕ собираем — и тренеру это сказано).
3. Обучение разбито на **~10 шагов**, исполняемых через **GitHub Actions**.
   Владелец настаивает, что раннер = 4 vCPU / 16 ГБ — **это ВЕРНО** для публичного репо
   (приватный даёт 2/8). Спорить не надо, просто пользоваться фактом.
4. **20–30 эпох** суммарно (реализуем как по 2–3 эпохи за запуск с чекпоинт-резюме).
5. В конце обучения — **программирование**: C++, C#, C, **плюс Python, Java, Mixins,
   Gradle, NeoGradle (Minecraft Forge/NeoForge)**.
6. Позже — **«файл-глаз»** (2D зрение для распознавания сред, напр. Unreal Engine;
   у владельца уже есть свой обученный проект в `main`: `ue5/`, `pretrain_ui.py`),
   и 3D (только заглушка-интерфейс).
7. Агент должен **управлять ПК владельца** (файлы) по просьбам.
8. Мечта — **приложение на ПК** с интерфейсом «как у Claude» (чужой UI не копируем,
   делаем своё простое окно; юридически и по качеству так правильно).

## 3. Железо владельца (важно для запусков)

- Ноут **Gigabyte G5 KD**: i5-11400H (6 ядер/12 потоков), **RTX 3060 Laptop 6 ГБ**,
  16 ГБ RAM, 512 ГБ SSD.
- Ограничения от владельца: **не трогать 1 ядро CPU** (из 6, он работает) и
  **GPU 0** (это Intel UHD — рисует экран). Учить только на **GPU 1**.
- ЛОВУШКА: в Windows «GPU 1» = RTX 3060, но у **CUDA** Intel UHD не видна,
  поэтому RTX 3060 имеет **CUDA-индекс 0**. Это уже решено в `src/gpu.py`
  (понимает "1" из Windows, "3060" по имени, "auto").

### 2026-09-20, вечер (продолжение) — прогон в Actions упал, разбор и починка

**Что случилось.** Владелец смержил PR #2 (фиксы данных поехали в `main`), прогон
пошёл — и упал на шаге обучения:

```
ValueError: Слишком мало токенов в shard_01: 232 < block_size+2
libgomp: Недопустимое значение переменной окружения OMP_NUM_THREADS
```

**Диагноз (оба бага — наши, в коде):**

1. **Порция меньше окна обучения.** Демо-корпус генерировался с `--scale 1`:
   домен `text` даёт 64 строки, а они раскладываются на порции 1..4 → ~232 токена
   на порцию, тогда как модели для одного окна нужно `block_size+2 = 258`.
   Хуже всего: генератор вызывался как `make_data.main()` — а `main()` читает
   `sys.argv` родительского скрипта, то есть масштаб вообще не задавался осознанно.
2. **`OMP_NUM_THREADS: "auto"` в workflow.** Значение `auto` понимает наш конфиг,
   но **не** libgomp/OpenMP — им нужно целое число. Строки `echo ... >> $GITHUB_ENV`
   влияли только на последующие шаги, а сама тренировка шла с `auto` в окружении.
   Рядом стоял `NUM_WORKERS: "auto"`, который `int("auto")` молча проглатывал —
   и `num_workers` оставался дефолтным.

**Что починено:**

- `src/data_utils.py`: порция меньше окна **повторяется до нужного размера** с
  предупреждением в лог (вместо падения). Пустая порция даёт читаемую ошибку с
  инструкцией, а не «232 < 258». Добавлены `shard_path()` и `shard_token_count()`.
- `steps/step_00_ci_data.py`: демо-корпус генерируется масштабом **x20** через
  отдельный процесс (`DATA_SCALE`), а не через `main()` с чужим `sys.argv`.
- `src/threads.py` (новый): `fix_thread_env()` — превращает `auto`/мусор/`0` в
  число, правильное значение не трогает. Вызывается при импорте `src`
  (до torch/numpy — libgomp читает переменную при загрузке), в каждом шаге
  01..10 перед `import torch`, и в оркестраторе.
- `src/config.py`: `NUM_WORKERS=auto` теперь становится числом ядер минус одно.
- `orchestrator.py`: шаги без данных **пропускаются с понятной причиной**, а не
  роняют прогон. В конце — сводка «обучено N, пропущено M» и что положить, чтобы
  включить пропущенные.
- `steps/step_00_prepare.py`: в отчёте по порциям помечает, какой порции мало и
  какого домена не хватает + печатает прогресс токенизации.
- `.github/workflows/pipeline.yml`: `OMP_NUM_THREADS` больше не `auto` — считается
  из `nproc` в том же шаге; добавлен `HF_TOKEN` (если секрет есть — быстрее HF).
- `.github/workflows/tests.yml`: добавлен `pyyaml` (нужен новым тестам).
- `tests/test_ci_robustness.py` (новый, 9 тестов): порция 232 токена не роняет шаг
  и данные именно повторяются; пустая порция говорит, что делать; `OMP_NUM_THREADS`
  `auto`/`abc`/`0`/`-3` → число; корректное значение не переписывается;
  `NUM_WORKERS=auto` → число.

**Осталось:** после мержа PR владельцем посмотреть прогон «Дообучение в Actions»:
данные (демо/Drive/HF) → токенизация → 1..2 шага → `checkpoints/step_01/last.pt` →
