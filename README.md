# AI-Learning

Пайплайн дообучения русской языковой модели (ruGPT-3 Small) с прогрессом
в GitHub Actions. Обучение ведётся на локальном GPU (ноут Gigabyte G5 KD,
RTX 3060 = GPU 1), Actions — дирижёр: шаги, чекпоинты, отчёт о прогрессе.

Плюс **ПК-агент** (`agent/`): скрещение обученных моделей с переключателем —
математика, код, чат-модель, зрение (2D + 3D-заглушка) и инструменты твоего
компьютера (файлы/команды в песочнице). Подробно: `docs/AGENT.md`.

## Дорожная карта

| Этап | Что | Где |
| --- | --- | --- |
| 0 | Сбор и чистка русского текста | `data/raw/*.txt` |
| 1 | Токенизация → 10 порций | `steps/step_00_prepare.py` |
| 2 | Обучение порций 1..10 (резюме с чекпоинта) | `steps/step_01.py … step_10.py` |
| 3 | Сводный отчёт + график loss | `steps/step_11_evaluate.py` |
| 4 | Автоматизация и прогресс | `.github/workflows/train.yml`, `.github/workflows/pipeline.yml` |

Домены в данных:
- **Русский текст / диалоги** — база и разговор (порции 1..4);
- **Математика** — арифметика, выражения, задачи (порции 5..6);
- **Код C / C++ / C#** — синтаксис и паттерны (порции 7..8);
- **Поведение / инструкции** — вежливость, следование просьбам, отсутствие обзывательств (порции 9..10).

## Быстрый старт (ноут, GPU 1)

```bash
pip install -r requirements.txt
pip install torch --index-url https://download.pytorch.org/whl/cu121

# положи .txt в data/raw/
python steps/step_00_prepare.py
python orchestrator.py --start 1 --end 10 --device cuda --gpu auto --evaluate
```

## Структура

```
├── config/train.yaml        # модель, гиперпараметры, пути
├── config/agent_config.yaml # конфиг ПК-агента
├── src/                     # ядро: config, данные, тренер, выбор GPU
├── agent/                   # ПК-агент: инструменты, память, эксперты, роутер, зрение
├── steps/                   # шаги 00..11
├── scripts/                 # данные: скачивание корпуса, генерация демо
├── orchestrator.py          # запускает диапазон шагов
├── data/raw/                # сюда класть .txt (не в git)
├── data/shards/             # токенизированные порции (не в git)
├── checkpoints/             # чекпоинты по шагам (не в git)
├── logs/                    # JSONL-журналы + progress.svg (не в git)
└── .github/workflows/       # Actions: запуск + прогресс
```

## Прогресс

Каждый шаг пишет `logs/step_NN.jsonl` (loss, lr, токен/с, время).
`step_11_evaluate.py` собирает всё в таблицу и `logs/progress.svg`.
В GitHub Actions всё дублируется в Job Summary + артефакт `ci-checkpoint-progress`.

## Важные решения (см. docs/SELF_HOSTED_RUNNER.md)

- GPU-обучение — на ноуте (RTX 3060, `CUDA_VISIBLE_DEVICES=1`); GitHub бесплатный
  стандартный раннер — 4 vCPU / 16 ГБ (публичный репо) без GPU, для коротких
  дообучающих прогонов.
- Эпохи: по 2–3 за запуск с резюме, суммарно до 20–30 (иначе перегрев и риск сбоя).
- Зрение «глаз» (распознавание сред, напр. Unreal Engine) — **отдельная** vision-модель:
  она не «зашивается» в текстовую; её добавлю, когда пришлёшь файл/датасет.
- Управление ПК по просьбе — **агент с инструментами** (tool-calling) поверх
  обученной текстовой модели: это код, а не обучение; добавляется сверху.

# Глаза для интерфейса Unreal Engine 5

Модель учится **видеть редактор UE5**: где вьюпорт, Outliner, Details и
Content Browser, в каком режиме находится редактор и какие иконки лежат на
панели инструментов.

## Главный принцип: только подлинные ассеты Epic

Кадры собираются кодом, но материал в них настоящий:

| что | откуда |
|---|---|
| цвета темы | `Engine/Source/Runtime/SlateCore/Private/Styling/StyleColors.cpp` |
| иконки | `Engine/Content/Slate/Starship/**/*.svg` — 242 файла |
| раскладка | стандартная схема окна редактора |

Подбирать цвета на глаз и рисовать «похожие» значки нельзя: агент выучит
интерфейс, которого не существует. Это уже проверено на соседнем проекте —
модель, обученная на выдуманных текстурах, на реальном скриншоте выдавала
уверенную чушь.

Ассеты Epic **не хранятся** в репозитории. Их скачивает команда:

```bash
python3 tools/fetch_ue5_assets.py
```

## Запуск

```bash
pip install -r requirements.txt
python3 tools/fetch_ue5_assets.py          # 662 файла, 3.8 МБ
python3 pretrain_ui.py --samples 12000 --epochs 25 --eval-every 5
```

Быстрая проверка, что всё живо:

```bash
python3 pretrain_ui.py --samples 300 --epochs 3 --width 320 --height 180
python3 -m pytest tests/ -q
```

## Чему учится модель

Общий свёрточный энкодер и три головы:

1. **Координаты панелей** — 6 коробок: viewport, outliner, details,
   content, toolbar, statusbar. Выход в долях кадра.
2. **Состояние редактора** — режим (`edit` / `play` / `simulate` /
   `paused`) и есть ли выделенный объект.
3. **Иконки** — какие из 40 пиктограмм Starship присутствуют на панели.

Энкодер тот же, что обкатан в Mine-AI: `Conv(3→32,8,s4) → Conv(32→64,4,s2)
→ Conv(64→64,3,s1) → Conv(64→64,3,s2) → Conv(64→32,1)`. На 640×360 это
12.4 млн параметров.

## Качество кадра

Кадр должен быть похож на настоящий снимок экрана, иначе сеть выучит
идеальные прямоугольники. Эталон замерен на реальных скриншотах редактора,
приведённых к 640×360:

| | детализация | цветов |
|---|---|---|
| настоящие скриншоты UE5 | 4.11 – 6.83 | 7 882 – 18 860 |
| **наш рендер** | **4.18** | **19 276** |
| голая отрисовка (было) | 3.81 | 261 |

Разница между «было» и «стало» — субпиксельное сглаживание, неравномерность
подсветки и слабый шум матрицы. Тест `test_frame_quality_matches_real_screenshots`
не даёт вернуться к плоским заливкам.

## Тесты

```bash
python3 -m pytest tests/ -q      # 12 passed
```

Главное, что они стерегут:

- цвета совпадают с `StyleColors.cpp` до байта;
- все пути иконок существуют (половина «очевидных» имён в UE5 не такая,
  какой кажется);
- разметка совпадает с картинкой — проверка по цвету пикселей внутри
  коробок;
- панели не перекрывают друг друга;
- кадр не скатывается в плоские заливки.

## Обучение в CI

`.github/workflows/train-ui.yml` — ручной запуск, скачивает ассеты, гоняет
тесты, обучает и выкладывает веса артефактом.
